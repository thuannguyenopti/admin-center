AI-Generated Page Quality Rubric

A shared evaluation framework for assessing whether AI-generated web pages meet production quality. Based on analytic rubric design principles (Allen & Tanner, 2006) with criteria applicable to any website regardless of CMS, framework, or design system.

Scope: AI-generated web pages Version: 1.0 Date: 2026-07-03 Dimensions: 5 Criteria: 18

Scoring Levels

Each criterion is scored on a three-point scale. Descriptors are cumulative: "Excellent" assumes all "Acceptable" conditions are also met.

3 — Excellent

Ready to publish. Indistinguishable from a hand-crafted page by a professional designer or editor.

2 — Acceptable

Usable with minor edits. Meets baseline requirements but has noticeable gaps a reviewer would flag.

1 — Poor

Requires significant rework. Structural, visual, or content issues that would block publication.

Quality Rubric

18 criteria grouped into 5 dimensions. Weights reflect relative importance to overall page quality. A page must meet the pass threshold defined below to be considered "good quality."

Dimension Criterion 3 — Excellent 2 — Acceptable 1 — Poor
1. Visual & Layout Correctness 30%
Visual & Layout Spatial consistency
  • Spacing follows a consistent scale throughout the page (e.g., 4/8/16/24/32px or the site's design tokens)
  • Consistent vertical rhythm between sections
  • No misalignment between sibling elements
  • Spacing is mostly consistent; 1–2 irregular gaps
  • Minor inconsistency in section margins
  • Arbitrary, inconsistent spacing throughout
  • Irregular gaps with no visible rhythm
  • Overlapping or clipped elements
Responsive behavior
  • Layout reflows cleanly from desktop to mobile
  • Images and media scale proportionally
  • No horizontal scroll at any viewport width
  • Touch targets are at least 44×44px on mobile
  • Desktop renders correctly; mobile has minor overflow or tight spacing
  • Breakpoints exist but some elements don't resize well
  • Fixed-width layout that breaks on smaller screens
  • Content overflows or is inaccessible on mobile
Visual parity
  • Generated page is visually indistinguishable from existing hand-built pages on the same site
  • Matches the site's established patterns for heroes, cards, grids, and sections
  • Recognizably belongs to the same site but with minor stylistic inconsistencies (e.g., different border radius, shadow depth, or font weight than existing pages)
  • Looks like a generic template; does not resemble the rest of the site
  • Mixes visual styles or introduces elements foreign to the site's design language
Color & theming
  • All colors come from the site's defined palette or design tokens
  • Foreground/background contrast meets WCAG AA (4.5:1 for text, 3:1 for large text)
  • If the site supports dark mode, the generated page renders correctly in both themes
  • Mostly on-palette; 1–2 off-brand colors
  • Contrast generally acceptable; one near-miss element
  • Colors unrelated to the site's palette
  • Text-on-background contrast failures making content hard to read
2. Component & Markup Quality 25%
Component & Markup Design system usage
  • Uses the site's established UI components (buttons, inputs, cards, navigation, etc.) rather than ad-hoc markup
  • Component variants are applied correctly (e.g., primary vs. secondary buttons used in appropriate contexts)
  • Core interactive elements use site components; 1–2 instances of custom markup where a component exists
  • Significant use of raw or custom-styled elements that bypass the site's design system
  • Inconsistent button styles, input styles, or card layouts on the same page
HTML semantics
  • Correct semantic elements used throughout (<nav>, <main>, <article>, <section>, <header>, <footer>)
  • No <div> soup; structure is meaningful to screen readers and search engines
  • Valid HTML with no parsing errors
  • Most structure is semantic; a few generic <div>s where a semantic element would be better
  • Entirely <div>-based structure with no semantic meaning
  • Invalid or malformed HTML
Image & media handling
  • Images are appropriately sized and optimized (not serving 4000px originals in 400px containers)
  • Responsive images use srcset or equivalent
  • All images have meaningful alt text; decorative images use alt=""
  • No broken image links or placeholder URLs
  • Images display correctly but are not optimized for size
  • Alt text present but generic (e.g., "image1.jpg")
  • Broken images, placeholder URLs, or missing media
  • No alt text on content images
  • Oversized images causing slow page load
Accessibility
  • All interactive elements have accessible names (visible labels, aria-label)
  • Keyboard navigable; focus order matches visual order
  • Color contrast meets WCAG AA throughout
  • Form inputs are associated with labels
  • ARIA landmarks present and correctly applied
  • Most elements accessible; 1–2 missing labels
  • Keyboard navigation works for primary flows
  • Multiple unlabeled controls or non-focusable interactive elements
  • Information conveyed by color alone with no text or icon fallback
  • No keyboard access to key features
3. Structural Consistency 15%
Structural Consistency Section completeness
  • All expected page sections are present (e.g., hero, feature highlights, social proof, CTA)
  • Section order follows a logical narrative flow
  • No empty, stub, or placeholder sections
  • Required sections present; order slightly rearranged but still logical
  • One optional section missing or underdeveloped
  • Missing critical sections (e.g., no CTA, no introductory content)
  • Placeholder text like "Lorem ipsum" or "[Insert headline here]"
Template fidelity
  • Output matches the selected template or page type in layout structure
  • Grid columns, content zones, and media placements align with the template spec
  • Content types match template slots (e.g., image where image is expected, text where text is expected)
  • Overall shape matches the template; minor deviations in grid or proportions
  • Output bears little resemblance to the selected template
  • Completely different layout structure than what was requested
Information hierarchy
  • Clear heading levels (H1 → H2 → H3) with no skipped levels
  • Visual weight matches content importance: primary CTA is prominent, secondary actions are subtle
  • Content flows logically; the reader's eye follows a natural path
  • Heading hierarchy present but one level skipped
  • CTA visible but not obviously the primary action on the page
  • No heading hierarchy; all text at similar visual weight
  • Primary CTA buried, missing, or competing with multiple equal-weight actions
4. Content Relevance 15%
Content Relevance Topical accuracy
  • All copy is on-topic and specific to the subject matter
  • No hallucinated facts, fabricated statistics, or non-existent features
  • Claims are plausible and internally consistent across the page
  • Mostly on-topic; 1–2 vague or generic sentences that could apply to anything
  • Fabricated details, invented product names, or factually incorrect statements
  • Generic filler text clearly unrelated to the intended topic
Content depth
  • Body sections contain substantive detail, not just headlines
  • Feature descriptions include benefit statements and supporting context
  • Content length is appropriate for the page type (e.g., ≥150 words for landing pages, concise for banners)
  • Content is present but thin; some sections read like outlines rather than finished copy
  • Headline-only content with no supporting detail
  • Significantly under the expected content length for the page type
Channel appropriateness
  • Tone, length, and format match the target channel and page type
  • Landing page: detailed, benefit-driven, SEO-aware. Email: scannable, CTA-focused. Social: concise, hook-driven
  • Metadata (title tag, meta description, Open Graph) present and correct for the channel
  • Broadly appropriate but some channel conventions missed (e.g., landing page copy is too brief)
  • Content clearly written for a different channel (e.g., social-length copy on a product page)
  • Missing essential metadata for the channel
Localization readiness
  • No text baked into images or hardcoded into layouts in a way that blocks translation
  • Date, number, and currency formats are locale-appropriate or parameterized
  • Text containers accommodate expansion (typically 130–150% for DE/FR/ES translations)
  • Most content is translatable; a few labels hardcoded in images or tight containers
  • Significant text baked into images with no text alternative
  • Rigid layouts that would break with translated (longer) strings
5. Brand Alignment 15%
Brand Alignment Tone & voice
  • Copy reflects the brand's defined tone attributes (e.g., "friendly and professional" vs. "bold and disruptive")
  • Voice is consistent throughout the page — no jarring shifts between sections
  • Follows documented voice guidelines (sentence structure, word choice, person/tense conventions)
  • Tone is broadly on-brand but inconsistent between sections
  • Occasional phrasing that doesn't match the brand's style (e.g., overly formal when brand is casual)
  • Tone contradicts brand guidelines (e.g., stiff and corporate when brand is playful)
  • Generic AI-sounding copy with no distinct brand personality
Visual brand
  • Colors are drawn from the brand's defined palette (primary, secondary, accent applied correctly)
  • Typography matches brand fonts for headings and body text
  • Logo/wordmark present in the correct position and size per brand guidelines
  • Imagery style (photography, illustration, iconography) is consistent with the brand's visual identity
  • Primary brand color correct; secondary or accent colors slightly off
  • Logo present but placement or sizing deviates from guidelines
  • Colors unrelated to the brand palette
  • Wrong, missing, or distorted logo; off-brand imagery
  • Typography doesn't match brand fonts
Brand guidelines compliance
  • All explicit rules in the brand guidelines are followed (clear space around logo, approved color combinations, messaging do's and don'ts)
  • Messaging aligns with the brand's positioning and value proposition
  • Legal requirements met (trademark symbols, disclaimers, copyright notices where required)
  • Guidelines mostly followed; one non-critical rule missed
  • Brand guidelines ignored or contradicted
  • Messaging conflicts with brand positioning
  • Missing required legal notices or disclaimers

Pass / Fail Threshold

A generated page is considered "good quality" when all of the following are true:

  • No criterion scores 1 (Poor) — any Poor score is a blocking defect that requires rework before publication.
  • Weighted average ≥ 2.5 — calculated as: ∑(dimension_avg × weight). A page scoring exactly 2.0 across all dimensions is functional but not publishable without editorial review.
  • Brand prerequisites met — the page's brand profile has colors defined, fonts configured, and tone/voice guidelines documented.
  • Accessibility floor — no WCAG AA contrast failures, all interactive elements keyboard-reachable, all images have alt text.

How to Use This Rubric

Context Method Outcome
Manual review Reviewer scores each of the 18 criteria 1–3 using the descriptors above. Takes 5–10 minutes per page. Scorecard with per-dimension averages and overall weighted score. Pages ≥ 2.5 pass; others get a list of specific criteria to fix.
Automated checks Criteria from dimensions 1–3 (Visual, Markup, Structure) can be partially automated via HTML validators, accessibility scanners (axe, Lighthouse), and design-token linters. Automated gate that flags poor-scoring criteria before human review. Reduces manual effort to dimensions 4–5 (Content, Brand).
AI self-evaluation Pass the rubric as context to the AI system. After generation, the AI scores its own output and flags any criterion below 3. Self-improvement loop: the AI re-generates sections that scored 2, surfacing only ≥ 2.5 pages to the human reviewer.
A/B comparison Score both a hand-built page and an AI-generated version of the same content. Compare per-criterion deltas. Identifies which quality dimensions the AI excels at vs. struggles with, informing prompt engineering and template improvements.

Methodology: Analytic rubric design based on Allen & Tanner (2006), "Rubrics: Tools for Making Learning Goals and Evaluation Criteria Explicit for Both Teachers and Learners," CBE—Life Sciences Education, 5(3), 197–203. Criteria derived from web content quality standards, WCAG 2.1 accessibility guidelines, and industry best practices for brand-consistent content production.

Maintenance: Review and update this rubric quarterly or when significant changes are made to brand guidelines, design systems, or content standards. Add new criteria only when an existing dimension cannot capture a recurring quality issue.
